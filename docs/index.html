Test SSO, provisioning and access audits before they touch production.

A SCIM 2.0 server, SAML and OIDC validators, Slack and GitHub org audits, and a SOC 2 evidence mapper, all runnable and testable on your laptop.

For platform, IT and security engineers who run Okta-style federation and want to exercise it, and gather audit evidence, without a vendor tenant.

How it fits together

From identity provider to audit evidence

SSO and provisioning are separate paths out of your IdP. Each produces events or state that the audit tools and the SOC 2 mapper read.

Based on the architecture section of the README. The Slack access-request app is not drawn: it approves requests and adds the requester to a SCIM group.

Quick start

Run it in a few commands

Commands are copied from the README. Python 3.11 or newer.

Install and run the tests

bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
pytest -q
ruff check .

Output from a real run in the README: 88 passed, 1 warning in 1.75s and All checks passed!

Run the SCIM server

bash
export SCIM_BEARER_TOKEN=demo-token
scim-server --port 8080 --store ./scim-data.json &

curl -s -X POST localhost:8080/scim/v2/Users \
  -H 'Authorization: Bearer demo-token' -H 'Content-Type: application/scim+json' \
  -d '{"schemas":["urn:ietf:params:scim:schemas:core:2.0:User"],"userName":"alice@example.com"}'

The README shows the created user back with "active": true. A request without the token returns 401.

Audit a GitHub org and produce SOC 2 evidence (offline fixtures)

bash
github-audit --org acme --offline-fixtures tests/fixtures/github/acme_routes.json --out gh.json
soc2-report --github gh.json --slack-audit slack.json --scim-store scim-data.json --format md

Run from a repo checkout. slack.json comes from slack-audit-logs and needs SLACK_AUDIT_TOKEN. Against a real org, drop --offline-fixtures and set GITHUB_TOKEN to a read-only token.

What is in the box

What is in the repo

Each part has its own tests and runs without a vendor account.

  • SCSCIM 2.0 server

    RFC 7643 and 7644 subset: Users, Groups, PATCH add, replace and remove, filters, pagination, constant-time bearer check, 409 on duplicate userName. Deprovision sets active: false.

    src/saas_governance_kit/scim

  • SASAML SP validator

    Verifies signatures against a pinned IdP cert and checks Audience, Destination, Recipient, InResponseTo and validity window with skew. Keeps a replay cache. Rejects unsigned, multiple assertions, duplicate IDs and DOCTYPE.

    .../saml/validator.py

  • OIOIDC validator

    JWKS with kid rotation refresh, algorithm allowlist, rejects none and HS* confusion, and checks iss, aud, azp, exp, iat and nonce.

    .../oidc/validator.py

  • SLSlack access request

    /access-request <group> <reason> with Approve and Deny buttons, an approver allowlist and no self-approval. Approval adds the requester to a SCIM group. Requests are verified with Slack v0 signing.

    .../slack/access_request.py

  • GHGitHub org audit

    Flags SAML credential authorizations, members without two-factor, unprotected default branches and outside collaborators. Ships a reusable workflow with a read-only token.

    .../github/

  • S2SOC 2 mapping

    Maps findings to CC6.1, CC6.2, CC6.3, CC7.2 and CC8.1 and writes Markdown or JSON. Evidence support only.

    .../soc2/

Also in the repo: Slack Audit Logs client (slack-audit-logs), a Terraform example that is only formatted and validated, a Dockerfile for the SCIM server, and CI.

Be clear about what is proven

Validated vs not validated

Nothing here has been run against a real Okta tenant, Slack Enterprise Grid or GitHub Enterprise. The fixtures were written by hand to match documented API shapes. They are not captures from a real tenant.

Copied from the README section "What is tested vs not tested".
AreaTested here
SCIM server15 pytest cases over FastAPI TestClient, including an Okta-style PATCH and a JSON-file store reload; a manual curl run and a Docker smoke test
SAML validator23 cases with a self-generated test IdP key and cert: valid, unsigned, tampered, wrong key, expired, skew, audience, destination, InResponseTo, replay, wrapping, DOCTYPE
OIDC validator22 cases with locally generated RSA and EC keys, including none, HS256 confusion, kid rotation
Slack access requestHandler unit tests with fake clients, SCIM client over a mock transport, Bolt dispatch against a local fake Slack Web API with signature checks
Slack audit logs7 cases against hand-written fixtures that follow the documented response shape; 429 and cursor handling via mock transport
GitHub audit7 cases against fixtures and a mock transport, including Link pagination and rate-limit backoff
SOC 2 mapping4 cases on fixture-derived input
Terraformterraform fmt -check, terraform init -backend=false, terraform validate
Reusable workflowYAML written and reviewed

SOC 2 output is evidence support. It is not a SOC 2 report, an attestation, a certification or a compliance claim. Whether a control is designed and operating effectively is for an auditor to decide.

Security notes: the SCIM server uses one static bearer token, so put it behind TLS. The SAML replay cache is in memory, so use a shared store if you run more than one instance.
